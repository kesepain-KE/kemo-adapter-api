# 先选任务，再按配方执行

这是低参数智能体的操作导航，不是让你一次修改整个项目。先读根目录
`agent_control.md`，然后只打开下面与你本次任务相符的一行。

## 先填任务卡

复制 [任务卡](../template/examples/task-card.md)，填入用户已确认的信息。
未知项写“未知”，不要猜，也不要把真实密钥填进任务卡。

必须知道：项目绝对路径、目标厂商、目标模型、本次操作。源代码版与部署版可能是两个目录；
没有确认目标时不要跨目录同步。只有目标或授权不清会阻止安全操作时才询问用户，
其他信息优先从现有源码、清单和测试中读取。

## 只选择一条路径

| 用户说的话 | 实际任务 | 下一份文件 |
| --- | --- | --- |
| 接一个新 API / 创建厂商 | 新厂商包 | [创建厂商](create-provider.md) |
| 给某厂商增加模型 / 注册模型 | 在已有包内增加目录项与映射 | [模型维护：增加模型](model-maintenance.md#1-增加一个模型) |
| 露出思考档位 / 修正能力 | 修改指定模型声明与真实适配 | [模型维护：修改能力](model-maintenance.md#2-更新现有模型能力) |
| 这个模型也能看图、听音频 | 给同一模型增加已验证操作 | [单模型多模态](multimodal.md) |
| 更换上游密钥 / 加备用密钥 | 修改厂商 secrets.json | [密钥操作](keys-and-secrets.md) |
| 给智能体换调用密钥 / 限制它能用的模型 | 修改网关 api/keys.json | [密钥操作](keys-and-secrets.md) |
| 只改 API 地址或超时 | 修改厂商 config.json，保留其他字段 | [密钥操作](keys-and-secrets.md) |
| 修改版本 / 准备发布 | 版本一致性、文档复核与分组全量验证 | [发布配方](release.md) |
| 减少统计查询读盘 | 网关内存读缓存，不是模型缓存 Token 计量 | [统计存储](../storage/README.md) |

不要把“增加模型”做成“创建另一个 Provider”，不要把“增加视觉能力”做成“全厂商开启所有模态”。

## 三种结果必须分开说

1. **离线结构通过**：代码能导入、声明能校验、模拟 Fixture 通过。不能据此说上游可用。
2. **目标上游验证通过**：用户授权后，使用目标账号、端点、模型做过对应最小真实调用。
   文本探测成功不证明工具、图片或音频成功。
3. **运行中生效**：需要重启的修改已按授权重启，用调用方自己的密钥重新获取目录与能力。
   尚未重启就写“已修改，待重启”，不要写“已上线”。

不要因本轮不能访问上游就把已有、经过验证的其他模型能力全部关闭。
只有本次新增且未验证的能力保持关闭；旧能力改动必须有证据和明确范围。

## 完成报告格式

```text
目标目录：
本次任务 / 厂商 / 完整模型名：
修改文件：
保留未改的内容：
离线测试：命令、数量、失败项
真实测试：已授权并执行 / 未执行及原因
能力证据：已验证项 / 未验证项（未公开支持）
生效方式：热更新 / 待重启 / 已重启并复查
Git：厂商包是否被忽略；是否提交或推送
后续用户需要做的事：
```

失败时报告具体字段和安全错误码，不复制原始响应、密钥或带签名的 URL。
