# 智能体操作网关

本目录是 **Kemo Gateway 2.0.0 的智能体操作手册**，供任何第三方智能体在用户授权后操控网关，不依赖特定智能体框架。用户向智能体提供网关根地址、获准的管理凭据和操作目标；智能体使用 HTTP 客户端或网络工具，按本手册完成提供商、密钥、模型、推理档位和路由等配置，网页中能看到相同结果。开始前读 [连接、认证与保存规则](connection.md)，再只读当前任务对应的手册。

## 完成一次操作

1. 确定用户要操作的网关地址、提供商、模型或密钥。先读取当前状态，使用真实 ID；显示名称相同但 ID 不同时，根据关联配置确定目标。
2. 使用用户已授权的管理身份，读取目录与权限。常规配置通过管理请求发布；不要直接改数据库、密文或运行中的 Python 对象。
3. 保存编辑开始时的 revision，只提交任务需要的字段。成功后重新读取目标对象，核对目录、凭据 ID、路由和模型权限。
4. 需要验证客户端能否使用模型时，用该客户端自己的调用密钥读取可用模型与能力。这一步不会生成内容。真实生成、能力探测和批量测试会产生上游请求，按用户已授权的范围执行。
5. 向用户说明修改对象、结果、生效方式，以及仍需用户提供的信息。报告用密钥名称和 ID，不输出真实 Token、密码或主密钥。

目录、路由、运行策略和密钥修改对后续请求生效，通常无需重启。启动文件保存、源码、依赖和构建产物变更需要重启；已有请求继续使用其开始时的目录代际。

## 常用任务顺序

**从零添加模型服务**：读取状态 → 选择已启用模板或自定义连接 → 保存提供商与上游密钥 → 发现或手填模型 → 登记选中模型 → 配置路由 → 创建有合适模型权限的调用密钥 → 用该密钥核对模型目录 → 将网关地址和公开模型名写入用户指定的客户端配置。

**更换上游密钥**：读取当前凭据池 → 保留其他凭据的 ID 和策略 → 添加或替换目标凭据 → 保存 → 读取脱敏结果。只有用户还要求连通测试时才执行真实模型调用。

**为智能体选择模型**：确认公开模型及其路由启用 → 确认智能体调用密钥允许该模型和任务 → 在客户端选择该公开名。网关没有一个对所有客户端生效的“当前选中模型”开关。

**删除服务**：按用户指定范围处理关联 Deployment，再删除提供商。删除整个公开模型会同时移除其全部路由和下游密钥中的对应白名单项；只移除一个来源时删除该 Deployment。
